# 四层可用性核验

**更新**：2026-11-04
**用途**：回答"现在四层都能用吗"这类问题。给出可复用的核验口径 —— **每层至少两条证据，缺一条不算可用**。

## 为什么需要这份清单

2026-11-04 复测踩到三个"看起来正常、实际不可用"的坑，直接用"端口在、文件在、脚本在"判断会误判：

| 坑 | 现象 | 真相 |
|---|---|---|
| 端口在 ≠ 能用 | ComfyUI `8188` 正常监听、能开界面 | `VAELoader` 等 4 类 loader 的 `/object_info` 返回 **500**，一执行工作流必挂 |
| 配置对 ≠ 生效 | `extra_model_paths.yaml` 已是正确路径 | 常驻进程启动于改配置之前，内存里仍是旧路径 |
| 文件在 ≠ 引用通 | 权重目录文件齐全 | 工作流是 subgraph 结构，顶层按键名解析会得到"引用 0 个模型"的假阴性 |

## 核验方法（逐层）

### L1 Draw Things CLI

```bash
cd <项目根>
bash scripts/start-drawthings.sh
```

判据：终端出现 `Wrote: .../outputs/drawthings/*.png` 且打印 `Total generation time`。读 `Total generation time`（含模型加载），不读 `real`（含进程启动）。

### L2 ComfyUI —— 必须三条件同时成立

```bash
# ① 服务在
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8188/system_stats

# ② loader 节点可枚举（关键，最易被漏）
for n in VAELoader CheckpointLoaderSimple LoraLoader UpscaleModelLoader UnetLoaderGGUF; do
  printf "%-24s %s\n" "$n" "$(curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8188/object_info/$n)"
done
# 全 200 才可用；任一 500 = 进程在读不存在的目录，需重启，见 runbook §2.1

# ③ 目标工作流引用的模型是否在盘
#    工作流为 subgraph 结构，模型引用藏在 definitions.subgraphs[].nodes[].widgets_values
#    按扩展名全量提取才可靠（.safetensors/.gguf/.ckpt/.pt/.pth/.bin）
```

### L3 stable-diffusion-webui

```bash
curl -s -m 10 -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7860/sdapi/v1/sd-models   # 200
curl -s http://127.0.0.1:7860/sdapi/v1/sd-models | python3 -c "import sys,json;print([x['model_name'] for x in json.load(sys.stdin)])"
```

再加一次真实出图（`/sdapi/v1/txt2img`）。只有列表不够 —— 列表正常而 MPS 推理失败的情况存在。

### L4 云端 API

```bash
[ -f scripts/.env ] && grep -c "API_KEY=." scripts/.env || echo "未配置"
```

判据：`.env` 存在、KEY 非空、且 `gen_cloud.py` 成功返回一次。**脚本就绪不算通。**

## 2026-11-04 复测结果

| 层 | 结论 | 证据 |
|---|---|---|
| L1 | **可用** | `flux_2_klein_4b_q6p.ckpt` 512×512 / 4 步，`Total generation time 29.49s`，采样均值 4.10s/步，产物 `outputs/drawthings/verify_L1_20261104-203136.png` |
| L2 | **可用** | 重启后（10s 就绪）6 类 loader `/object_info` 全 200；模型可见性恢复（VAE 3 项、ckpt 3 项含 legacy-sd15、LoRA 5 项）；flux2-klein-4b 蒸馏分支 512×512 / 4 步出图 **81.2s**（首次含加载），产物 `outputs/comfyui/verify_L2_20261104_00001_.png`。修复前状态见文末「L2 故障根因」 |
| L3 | **可用** | `/sdapi/v1/sd-models` HTTP 200，已加载 `chomni` / `CounterfeitV25_25`；此前同链路 SD1.5 + LoRA 出图 117.7s |
| L4 | **未通** | `scripts/.env` 不存在，无 API KEY |

**结论：** L1 / L2 / L3 均已实测跑通（数据见上表），唯一缺口是 L4 —— `scripts/.env` 未配 API KEY，配上即可闭环。

## 附：L2 故障根因（本轮实测）

ComfyUI 进程（PID 64531，16:36 启动）加载的是改配置**之前**的 `extra_model_paths.yaml`。`folder_paths.get_filename_list()` 会把每个候选目录的列表与 mtime 缓存在内存，其中仍含旧路径 `<SSD卷>/<旧权重目录>/*`；该目录在整理中已改名为 `ai-image-lab/models/*`，于是每次枚举都抛 `FileNotFoundError`。

配置侧现已全部正确（`ai_image_lab` 10 个子目录 + `legacy_a1111` 5 个子目录逐个核对，均存在），**重启进程即恢复**——当日已验证：重启 10s 就绪、6 类 loader 全 200、出图 81.2s。
