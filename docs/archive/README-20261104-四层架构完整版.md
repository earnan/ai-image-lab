# AI Image Lab — macOS 本地出图四层架构

M2 Mac mini 16GB / 外置 SSD 方案。按速度分层，就近选用。

## 磁盘分工

| 卷 | 角色 | 内容 |
|---|---|---|
| `<SSD卷>` (外置 SSD, APFS ~328MB/s) | 引擎 + 模型 | `ai-image-lab/apps/` 程序与 venv，`ai-image-lab/models/` 共享模型根 |
| `<HDD卷>` (机械盘 ~92MB/s) | 工作区 | `work/projects/ai-image-lab/` 工作流、脚本、产物 |
| 内置盘 | 不放模型 | 仅系统 |

> 模型绝不放 HDD：GGUF 2.3GB 在 HDD 上加载需 25s+，SSD 上约 3s。

## 四层架构

| 层 | 引擎 | 定位 | 512@4步 实测 | 状态 |
|---|---|---|---|---|
| **L1** | Draw Things CLI | 苹果原生 Metal，最快日常出图 | **23s** | ✅ 可用 |
| **L2** | ComfyUI + GGUF | 全能工作流引擎，节点可编排 | **54s** | ✅ 可用 |
| **L3** | stable-diffusion-webui | 老工作流/SD1.5 生态、LoRA | ~30s (SD1.5) | ✅ 已有 |
| **L4** | 云端 API | 本地跑不动或要高画质时兜底 | 10-30s | ⚙️ 待填 KEY |

### 分层选用建议
1. 日常快速出图 → **L1**（比 L2 快 2 倍以上）
2. 需要图生图/ControlNet/复杂节点编排 → **L2**
3. 跑老 SD1.5 模型与 LoRA → **L3**
4. 要 4K、复杂构图、本地内存不够 → **L4**

## 快速开始

### L1 — Draw Things（最快）
```sh
cd <SSD卷>/ai-image-lab/apps/draw-things
export DRAWTHINGS_MODELS_DIR=<SSD卷>/ai-image-lab/models/drawthings
./draw-things-cli generate \
  --model flux_2_klein_4b_q6p.ckpt \
  --prompt "your prompt" \
  --width 512 --height 512 --steps 4 \
  --output <HDD卷>/work/projects/ai-image-lab/outputs/out.png
```
图生图加 `--image input.png --strength 0.35`。

### L2 — ComfyUI
```sh
<SSD卷>/ai-image-lab/scripts/start-comfyui.sh
# 浏览器打开 http://127.0.0.1:8188
# 左侧 Workflows 面板选 01-flux2-klein-4b-t2i（已配好 GGUF 量化）
```

### L4 — 云端兜底
```sh
cd <SSD卷>/ai-image-lab/scripts
cp .env.example .env      # 填入 DASHSCOPE_API_KEY 等
python gen_cloud.py "your prompt" --size 1024x1024
```

## 关键性能数据（实测）

| 引擎 | 512@4步 | 768@4步 | 1024@4步 |
|---|---|---|---|
| Draw Things (q6p) | 23.3s | 37.5s | 58.3s |
| ComfyUI GGUF Q4_0 | 54.2s | 64.7s | 128.5s |
| ComfyUI fp16 | 138-166s | — | — |

> fp16 全套 14.7GB 占满 16GB 统一内存，触发 14.8GB swap，速度反而慢 2.5 倍。**GGUF 量化是 16GB 机器的必选项。**

## MPS 注意事项

- GGUF 只能用 **Q4_0 / Q4_1 / Q5_0**；Q4_K_M / Q5_K_M 在 Apple MPS 上出坏图
- 不支持 FP8；不支持 CUDA
- FLUX.2 Klein 4B 蒸馏模型最少 4 步，CFG 固定 1.0
